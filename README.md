# BOSS 直聘岗位沟通脚本

在 Windows PowerShell 中使用。需要 Node.js 22 或更高版本，以及本机安装的 Google Chrome。

## 启动

在项目目录执行：

```powershell
npm install
npm run login
```

在打开的专用 Chrome 窗口中手动登录 BOSS 直聘。登录完成后执行：

```powershell
npm start
```

后续可直接运行 `npm start`。脚本复用项目下 `.chrome-boss` 中的登录状态。请一次只运行一个脚本实例。Chrome 如果安装在自定义位置，在启动前通过 `$env:BOSS_CHROME_PATH` 指定 `chrome.exe` 的完整路径。

## 运行行为

- 每次打开指定列表，从第一条岗位开始。通过鼠标移动、点击和滚动按顺序处理。
- 右侧详情匹配当前岗位后，看到「继续沟通」就跳过。看到「立即沟通」后依次点击「立即沟通」和弹窗内的「留在此页」，确认弹窗关闭才继续。
- 页面状态分别等待最多 10 秒。两次点击至少间隔 2 秒，完成或跳过一条岗位后，至少间隔 3 秒再点击下一条。这两个间隔与页面等待独立计时。
- 出现验证码、平台限制提示、未知弹窗、页面跳转、无法确认目标或超时，脚本退出并保留 Chrome 页面。按 `Ctrl+C` 也可以停止。
- 异常时，`logs` 下保存 JSON 和当前可视区域截图。页面关闭或浏览器阻止截图时，JSON 会记录原因。日志的 `chatAttempted` 表示已尝试点击「立即沟通」，需要在保留的页面中核对结果。

实际执行时会发起沟通。`npm start` 通过 Windows 无障碍接口读取普通 Chrome，再操作系统鼠标。请保持打开的岗位窗口在前台，运行时避免操作鼠标。`npm run check` 使用相同的界面读取逻辑验证第一条岗位，全程不点击、不滚动。

## 页面反复跳转

先按 `Ctrl+C` 停止脚本，关闭脚本专用 Chrome 的所有窗口，再运行 `npm run open`。这个命令使用同一登录配置，按普通方式启动 Chrome。它只打开岗位列表。

如果之前运行过旧版，请先关闭旧版打开的所有脚本专用 Chrome 窗口，再运行新版 `npm start`。新版以普通方式启动 Chrome。遇到异常时请查看 `logs` 内最新的 `*-native-*.json` 和对应截图。
